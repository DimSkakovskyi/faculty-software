# Лабораторна робота №1 — пакети прикладних програм факультету

Консольна інформаційна система на **Haskell** із базою даних **MySQL**. Проєкт виконує варіант 8: облік пакетів прикладних програм, які розробляють студенти й викладачі факультету, а також семінарів, демонстрацій і тестових випробувань цих пакетів.

## Можливості

- Перегляд, пошук за частиною назви, додавання, редагування та видалення програмних пакетів.
- Облік студентів і викладачів; призначення їх розробниками пакета із зазначенням ролі.
- Планування семінарів, демонстрацій і випробувань; облік учасників семінарів та результатів випробувань.
- Перегляд усіх заходів вибраного пакета через консольне меню.

У меню доступні пункти `1`–`25`; `0` завершує програму. Після номера пункту та кожного введеного значення потрібно натиснути **Enter**. Програма позначає обов'язкові й необов'язкові поля та перевіряє додатні ID, дозволені значення статусів і формат дати.

## Вимоги

- GHC 9.10.3 і Cabal (конфігурація використовує `base ^>=4.20.2.0` та `cabal-version: 3.16`).
- Запущений MySQL Server за адресою `127.0.0.1:3306`.
- MySQL Workbench або інший клієнт MySQL для створення бази зі скрипту.

Пакети Haskell (`mysql-haskell`, `io-streams`, `text`, `bytestring`, `time`) перелічені у `faculty-software.cabal` і встановлюються Cabal під час збірки.

## Структура проєкту

```text
faculty-software/
├── app/
│   └── Main.hs                 # Меню, введення та виведення
├── src/
│   ├── Database.hs             # Підключення до MySQL
│   ├── DbUtil.hs               # Виконання параметризованих SQL-запитів
│   ├── Models.hs               # Типи даних, class та instances
│   ├── PackageRepository.hs    # Пакети та їх розробники
│   ├── PersonRepository.hs     # Студенти й викладачі
│   └── EventRepository.hs      # Семінари, демонстрації, випробування
├── sql/
│   ├── schema.sql              # Створення бази й таблиць
│   └── seed.sql                # Необов'язкові навчальні дані
├── faculty-software.cabal
└── README.md
```

## База даних

База `faculty_software` містить **7 таблиць**:

| Таблиця | Призначення |
| --- | --- |
| `persons` | Студенти й викладачі |
| `software_packages` | Програмні пакети, їх версії та статуси |
| `package_developers` | Зв'язок людей із пакетами та ролі в розробці |
| `seminars` | Теми, дати й місця семінарів |
| `seminar_participants` | Учасники семінарів |
| `demonstrations` | План демонстрацій |
| `test_trials` | План, статуси й результати випробувань |

Зовнішні ключі підтримують зв'язки між таблицями. Для пов'язаних записів використано `ON DELETE CASCADE`: **видалення пакета також видалить його семінари, демонстрації, випробування та зв'язки з розробниками**.

### Створення бази

1. Переконайтеся, що MySQL Server працює.
2. У MySQL Workbench відкрийте підключення до сервера, а потім `sql/schema.sql` через **File → Open SQL Script**.
3. Виконайте весь скрипт (**Execute All or Selection**). Для створення бази й таблиць користувач MySQL повинен мати відповідні права.
4. За потреби відкрийте й виконайте `sql/seed.sql` для прикладів. **Виконуйте його лише один раз**: повторний запуск зіткнеться з унікальними email.

Перевірка у Workbench:

```sql
USE faculty_software;
SHOW TABLES;
```

Має відображатися сім таблиць. `CREATE TABLE IF NOT EXISTS` не змінює структуру таблиці, яка вже існувала раніше; якщо у вас стара схема, порівняйте її зі скриптом.

## Запуск у Windows

Програма підключається до бази `faculty_software` на `127.0.0.1:3306`. Вона запитує ім'я користувача MySQL і пароль. Натискання **Enter** у полі користувача обирає `lab_user`; якщо налаштовано лише `root`, введіть `root`. Пароль під час введення не відображається. Обліковий запис має мати права на читання й зміну даних у базі.

У PowerShell:

```powershell
cd C:\Users\Dmytro\Documents\faculty-software
cabal build
cabal run
```

За потреби замість інтерактивного введення програма може прочитати змінні середовища `FACULTY_DB_USER` і `FACULTY_DB_PASSWORD`. Не зберігайте справжній пароль у вихідному коді чи README.

## Перевірка роботи

1. Пунктом `7` додайте людину; пунктом `6` подивіться її фактичний ID.
2. Пунктом `3` додайте пакет; пунктом `1` подивіться його ID, а пунктом `2` знайдіть за частиною назви.
3. Пунктом `11` призначте людину розробником пакета; пунктом `10` перевірте зв'язок.
4. Пунктами `14`, `20` і `23` додайте семінар, демонстрацію та випробування. Пункт `13` має показати всі три заходи. Учасника семінару можна додати пунктом `18` і переглянути пунктом `17`.
5. Змініть версію або статус пакета пунктом `4`; повторіть перегляд пунктом `1`.
6. Вийдіть пунктом `0`, знову запустіть `cabal run` і переконайтеся, що записи збереглися.

Для дати й часу використовуйте формат `РРРР-ММ-ДД ГГ:ХХ:СС`, наприклад `2026-10-15 14:00:00`. Не припускайте, що новий запис отримав ID `1`: після додавання перегляньте список і візьміть фактичний ID.

## Використання `class` та `instance`

У `src/Models.hs` визначено клас типів `DbEntity` із методами `entityId` і `displayName`. Для нього реалізовано два екземпляри — `Person` та `SoftwarePackage`. У `app/Main.hs` метод `displayName` використовується в повідомленнях про додавання людини чи пакета. SQL-операції зосереджені в окремих модулях `Repository`.

## Відомі обмеження

- Успішне `cabal build` підтверджує компіляцію, але не перевіряє підключення до вашого MySQL і виконання всіх SQL-запитів. Потрібен практичний прогін меню.
- Повідомлення `SQL-запит виконано` після `UPDATE` чи `DELETE` означає, що MySQL не повернув помилки; програма наразі не перевіряє, чи існував запис із введеним ID. Результат слід підтверджувати повторним переглядом.
- Під час редагування потрібно ввести значення всіх полів, які показує відповідний пункт меню; залишення необов'язкового поля порожнім передає порожній текст.
